# US-10 — Mensajería instantánea

Rama: `feature/US-10-mensajeria-instantanea` (parte de `feature/US-07-editar-eliminar-salas`). Consume el servidor de tiempo real de `backend-realtime` (PR #4): `sala:unir`, `chat:enviar`, `chat:mensaje` y `sala:presencia`. Los mensajes los guarda el servidor en Firestore; el frontend no consulta Firestore.

## Implementación

- Una sola conexión Socket.IO por sala (`useSalaEnVivo`), con el ID token en el handshake. Se cierra al salir.
- **Enviar:** Enter envía, Mayús + Enter agrega una línea. Un mensaje vacío o solo con espacios no se envía (se explica y el foco queda en el campo); el límite de 2000 caracteres coincide con el del servidor. Si el envío falla, el texto se conserva. Una referencia impide doble envío.
- **Recibir:** solo se aceptan mensajes bien formados cuya `salaId` es la de la sala abierta. Cada mensaje muestra autor, hora y texto; los propios se distinguen con alineación, color y la etiqueta «Tú» (no solo por color). Se evitan duplicados por `id`.
- **Desplazamiento:** si estás al final, baja sola; si lees mensajes anteriores no te mueve y aparece el botón «Mensajes nuevos (n)». Los propios siempre bajan.
- **Participantes:** lista que entrega el servidor (anfitrión primero, sin duplicar pestañas), actualizada con `sala:presencia`.
- **Reconexión:** al reconectar se vuelve a entrar a la sala; hasta confirmar no se puede escribir y se explica.
- **Estados:** cargando («Conectando…», «Buscando quién está en la sala…»), vacío («Aún no hay mensajes…»), error (mensaje del servidor, sin conexión) y éxito («Chat en vivo»).
- «Volver a mis salas» pasa a **«Salir de la sala»** dentro de una sala; siempre está visible.

## Accesibilidad (WCAG 2.2)

- Región `role="status"` oculta a la vista que anuncia, sin mover el foco: mensajes de otras personas («ana escribió: …»), entradas y salidas, y «Mensaje enviado.» (4.1.3). La propia entrada no se anuncia.
- La lista de mensajes es una región con nombre y foco de teclado (2.1.1); cada mensaje se lee en orden autor, hora y texto; la hora usa `<time>`.
- Campo con etiqueta, ayuda de teclado asociada (`aria-describedby`) y errores con `role="alert"` y `aria-invalid`.
- Zonas con encabezados: Chat de la sala, Participantes, Comparte tu sala/Administrar sala (`<aside>` con nombre).

## Comprobación

```bash
npm run build && npm test && npm run lint
```

Además se probó el servicio con `socket.io-client` real contra un servidor local con el mismo contrato (entrada, presencia y mensajes entre dos usuarios).

## Evidencia pendiente en producción

1. Tres navegadores (dispositivos distintos) en 2 salas: los mensajes llegan solo a su sala, con nombre, hora y texto.
2. Mensaje vacío (no se envía), Enter envía, mensaje de más de 2000 caracteres (error).
3. Leer mensajes anteriores y recibir uno nuevo: aparece «Mensajes nuevos».
4. Entrar y salir con otra cuenta: la lista de participantes cambia.
5. Cortar y recuperar la red: aviso de reconexión y chat operativo.
6. Teclado y NVDA/VoiceOver (anuncios sin mover el foco); Lighthouse ≥ 95; capturas en celular. Anexar al DUE y al PR.
